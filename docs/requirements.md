# Требования к системе управления заказами кузовной мастерской

## 1. Общее описание
Кузовная мастерская принимает автомобили, оценивает объём кузовного ремонта, выполняет работы и выдаёт авто клиенту. Сейчас учёт ведётся в Excel — нет прозрачности по срокам и стоимости. Цель проекта — создать веб-систему, которая автоматизирует полный цикл заказа.

## 2. Роли
| Роль      | Описание |
|-----------|----------|
| Клиент    | Просматривает статусы своих заказов, загружает фото повреждений |
| Менеджер  | Создаёт заказ, рассчитывает смету, согласует с клиентом |
| Мастер    | Фиксирует выполненные операции ремонта |
| Администратор | Управляет справочниками услуг и пользователями |

## 3. Жизненный цикл заказа
1. Создание заказа менеджером  
2. Оценка и расчёт сметы  
3. Согласование сметы с клиентом  
4. Выполнение ремонта  
5. Выдача автомобиля и закрытие заказа  

## 4. Функциональные требования
| ID | Требование |
|----|------------|
| FR-01 | Система должна позволять менеджеру создавать заказ с привязкой к клиенту и автомобилю |
| FR-02 | Система должна автоматически рассчитывать стоимость заказа на основе справочника работ и нормо-часов |
| FR-03 | Клиент должен иметь возможность загружать до 5 фото повреждений (JPEG/PNG ? 5 МБ) |
| FR-04 | Мастер может менять статус заказа на «В работе», «Готово» |

## 5. Нефункциональные требования
| ID | Требование |
|----|------------|
| NFR-01 | Время отклика REST-API < 300 мс (95-я перцентиль) |
| NFR-02 | Система должна выдерживать 20 одновременных пользователей без деградации |
| NFR-03 | Резервное копирование базы данных не реже одного раза в сутки |
